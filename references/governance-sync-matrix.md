# 文档治理变更影响矩阵

仅在文档承载的事实改变或用户要求治理审查时，定位受影响的主记录。此表不是每次收尾的检查清单；普通小修只改代码、跑相关检查，文档事实未变就零文档更新，不运行全量审计。

## 事实变化与主记录

| 改变的事实 | 按需更新 |
|---|---|
| 路径、知识入口或非显然定位关系 | MAP 对应导航及失效引用；不记录实现过程或测试结果 |
| Module 权责、状态归属、依赖方向或核心流转 | 已有架构主记录；按 `architecture-docs` 判断，无需重抄到 MAP |
| 用户操作、运行命令、配置或部署方式 | 受影响的 README、使用或部署说明；不按文件名自动联动 |
| 公共 API、消息或数据格式 | `CONTRACT.md` 指向的唯一契约与使用说明；入口位置未变不改 MAP |
| 领域术语与采用口径 | 已有 CONTEXT 或领域主记录；未确认不猜测 |
| 难回退的架构、数据或认证决策 | 按 `domain-modeling` 沿用既有决策主记录；只在需要独立追溯时建立 ADR |
| 已确认需求、成功标准或迭代范围 | 现有 Spec／Issue 或产品主记录；不复制任务状态或补齐全部阶段 |
| 测试入口、运行方法或重要覆盖范围 | TESTS 对应条目；普通 Bug、新增边界用例、重复绿色结果不触发登记 |
| 下游依赖或可执行回归命令 | 已有 REGRESSION 对应条目；验证实际受影响范围，不自动全量回归 |
| 需持续交接的风险、阻塞或关键健康状态 | 已有 STATUS 或 Tracker 主记录；已结束的小任务不留流水 |
| 易被误恢复的删除或废弃 | 现有删除提醒位置，写明原因和替代入口；普通删文件不自动写 STATUS／LOG |
| 长期项目硬规则 | 共享项目入口；专属细节留局部主记录 |
| 文件归位或自动审计触发约定 | 项目位置配置、对应实现及真实使用说明；不代作业务决策 |
| 重大交付、关键决策、重要故障或迁移 | 既有历史主源留一份原因、依据与版本；已采用 LOG 时只追加，不重复抄入其他载体 |
| 排期、负责人或任务状态 | Issue Tracker，不复制进 MAP、STATUS 或 LOG |

## 使用边界

- 从本次实际 diff 判断事实是否变化，直接修正受影响主记录和必要引用；事实未变即可交付，无需逐份核对全部治理文档。
- MAP 告诉读者去哪里找；LOG 解释重要历史。二者不互作流水账，也不要求每次同时更新。
- 验证按影响和风险选择，既有有效结果可复用；只有新变化、失败或未覆盖风险才补跑。结果在回复说明即可，不为绿色结果新建记录。
- 全项目审计仅用于明确的整体审查、全局治理结构变化或适用的既有门禁；普通收尾不触发。
- 事实和授权不明时说明缺口，不编造指标或改写已确认需求；保留历史原文，不用 LOG 代替当前事实修正。
- 架构、测试台账、ADR 等沿用已有载体，不为凑齐表格创建文档。重要事实只维护一份主记录，其他位置需要时引用。
