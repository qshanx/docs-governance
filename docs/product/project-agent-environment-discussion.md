## 建议的环境治理路径

先认识现有环境，再补真实缺口；任务结束或出现阻力时，用 Matt 的复盘方法回查环境。小项目按实际需要处理，不铺设完整工具平台。

| 环节 | 需要回答 | 候选产物与完成依据 |
|---|---|---|
| 了解现状 | 什么项目、什么宿主、已有入口和工具是什么，限制在哪里？ | 实际文件／配置／命令证据和缺口；未知保持未知 |
| 搭建或修正 | 哪些入口、上下文、工具访问、权限或执行条件确实缺失？ | 最小配置／导航方案，注明影响、授权和恢复方式；确认后再实施 |
| 运行衔接 | Agent 能否找到必要资料、获得信息、在允许范围执行并反馈结果？ | 一条代表性工作路径；写入范围与责任方明确 |
| 环境复盘 | 本轮哪里绕路、缺信息、规则失效或交接不清？ | Matt 式候选清单：证据、影响、实际落点、验证办法 |
| 持续维护 | 哪些已改善，哪些仍待处理，旧规则是否还有效？ | 更新原有主记录和处理任务；实际效果与配置完成分开报告 |

这不是要求每个任务执行五轮流程，也不代表开启后台 loop。无相关问题时结束；需周期运行另行明确范围、预算与停止条件。

## 环境治理的范围

| 方面 | Project 关注什么 | 不在本职责内的工作 |
|---|---|---|
| 上下文与知识入口 | 项目规则、地图、已确认决定、按需读取、会话交接与过时资料 | 代替产品负责人制定业务要求 |
| 方法与资料组织 | Skill 的触发、输入输出、附件读取条件，避免重复主源 | 扩写全部专项方法或为每种问题新建 Skill |
| 工具与信息 | 工具是否真实可用，日志／只读访问是否足够，输出是否可追溯 | 无依据安装所有推荐工具、默认接入真实账号 |
| 权限与控制 | 写入范围、确定性检查的调用、失败处理和恢复方式 | 自动授权合并、发布或扩大权限 |
| 隔离与协作 | 工作区、任务依赖、文件所有权及集成责任；是否确有隔离需要 | 为了形式固定派多个 Agent |
| 验证执行环境 | 现有检查命令、依赖、收集／调用入口、日志回执能否使用 | 设计业务测试、补断言／fixture、维护测试必要性或审核 PR |

最后一行只关注环境链路。发现业务测试缺口时，交接来源与现象，不在 Project 内继续完成测试复盘；测试为何存在、保护什么以及记录方式在 [Issue #49](https://github.com/qshanx/docs-governance/issues/49) 讨论。

## 错题本与状态记录

Project 不以新建错题本、累计次数或三次自动升级为前置流程。任务进度、环境事实、决定和改动沿已有主记录保存；Skill 本身是方法，不能假装已经自动积累经验。

## 确认后的验证候选，尚未执行

先确认职责、承载位置、最小输入输出和验收条件，再选择小范围试点，例如已有环境复用、现有检查未接通、资料导航误导、缺少日志、只读复盘及无需改动的任务。

这些候选不能由链接检查、现有单测或以前混合工作区的试跑替代。本 PR 只运行仓库对文档提交要求的结构、链接、历史与提交快照检查；不继续实施或测试新治理流程，不宣称环境搭建已经完成。
