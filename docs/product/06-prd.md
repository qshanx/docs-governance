# 产品文档管理能力

阶段状态：已完成（本轮范围成文）。文档修订：r3。日期：2026-09-23。状态：本轮建设方向、十阶段文件顺序、范围、管理员角色、PM 四类索引与按任务读取已确认；实际验证以审查记录为准。文档修订不代表插件发布版本；r1、r2 及护栏追加记录从 Git 历史追溯。

## 背景与用户

长期与 AI 协作的产品负责人和研发维护者，需要知道当前产品要求及其依据。反馈、决定、PRD 与任务分散时，后续 Agent 容易沿用旧需求，或把任务关闭误认成产品验收完成。

本次来源是阿磊在当前会话引用向阳 PRD 管理讨论，要求将方法加入本插件，随后明确“在 docs 里面有一个专门进行管理的地方，然后审查”。向阳的目录与规则是参考案例，不作为本插件历史需求的批准来源。

## 目标与用户路径

1. 用户要求建立产品管理空间，Agent 先发现已有产品资料与任务来源。
2. 在 docs 下复用或创建专门入口，指出整体／模块要求、当前生效修订、决定来源、任务与验收证据。
3. 需求变化时沿已有决定更新主记录，涉及整体方向时同步整体说明，开发进度继续由任务工具维护。
4. 用户要求审查时，Agent 先查文档完整性，再查需求、决定和验收证据是否一致，报告问题与未验证项。

## 本轮范围

交付一个共享 Skill、一份入口模板、按“项目初始化 → 市场分析 → 需求调研 → 需求分析 → 原型 → PRD → 需求评审 → 研发 → 测试上线 → 运营反馈”组织的本插件产品管理目录，并接入总路由、用户说明、地图与阶段同步。遵循现有宿主共用方法论结构。

本轮追加已确认的文件护栏：按变更触发收尾审计、提交暂存区强制检查、复用现有 PR CI；不增加每日定时任务。必需文件、关键词与允许位置由项目声明。

2026-09-22 阿磊进一步确认：沿用业务项目已有文档驱动规则，提交 PR 前强制触发扫描。交付 pre-push 钩子与同一 PR CI 检查入口：按真实提交差异定位关联文档，在独立提交快照审计；确定性失败阻止继续，语义同步仍由 Agent 审查。已有项目目录不迁移，不新增评估流程。

不包含外部看板配置、自动埋点、完整历史 PRD 迁移或发布。已有 PM 技能可辅助产出，安装它们不是使用本能力的前提。

方法仅管理各阶段文档，不执行市场分析、专业评审、研发测试或运营判断。

2026-09-23 阿磊确认管理员角色设计：新增 `product-docs-manager` 作为 Claude Code 适配层，Codex / ChatGPT 直接执行同一 Skill。六类资料组织为“原始输入 → 产品认知与规划 → 需求池 → 单需求 → 版本 → 验收复盘”，与已有十阶段导航链接复用。来源先登记，编号沿用且稳定，状态和版本有唯一维护位置；Markdown 维护需求与决定，导出交付物关联修订，原始文件保留为证据。文件修改及正式状态变更须有明确授权，已有同范围授权不重复确认。规则只扩展现有 Skill 和入口模板，不改业务项目或增加状态服务。

2026-09-23 阿磊进一步确认（来源 PDR-20260923）：材料按 PM 的产品发现、市场研究、产品战略、产品执行四类登记，与六类管理记录及十阶段导航共用原有主记录；新增按任务读取协议，避免 PRD 增长导致默认全量加载。共享 Skill 保存完整方法，CLAUDE 及其模板只保留触发路标，AGENTS 继续薄桥接。索引定位当前需求及修订，按影响补读公共规则、相关条款和依据；全产品审查分批登记覆盖。这里只约束读取方法，不增加上下文监控脚本或承诺固定 token 上限。

## 验收条件

| 编号 | 可观察条件 | 验证方式 |
|---|---|---|
| PE-1 | 十阶段文件齐全，从项目地图与总路由能找到产品入口及方法论 | 核对真实文件、引用与路由 |
| PE-2 | 方法能区分草案与生效版、部分批准、文档修订与发布及验收 | 按场景逐条审阅 Skill 与模板 |
| PE-3 | 复用现有 Spec／Issue，不制造第二套任务状态或验收标准 | 核对职责及更新流程 |
| PE-4 | 审查有证据、分级、未验证与权限边界，不能用脚本通过代替业务验收 | 核对审查流程和本轮审查记录 |
| PE-5 | 插件结构、单元测试及文档链接检查通过 | 运行标准 verify 与 Skill 格式验证 |
| PE-6 | 错放的 PRD／脚本和缺失入口被拒绝；普通正文提及关键词不误报 | 真实文件、规则与例外的集成测试 |
| PE-7 | 收尾只在变化后重跑，提交检查暂存快照，错误配置不得判绿 | Stop 与暂存区集成测试；现有 PR CI 复验 |
| PE-8 | 管理员角色可发现并调用既有 Skills；六类与十阶段引用同一主记录，编号稳定，未授权不写入且授权不越界 | 核对 Agent、路由、模板及来源／状态／导出场景；标准 verify |
| PE-9 | PM 四类索引、六类管理位置与十阶段链接同一主记录，现有文件不为分类迁移或复制 | 核对 Skill、模板和本项目映射 |
| PE-10 | CLAUDE 触发当前基线定位；单需求补读必要规则、依赖与确认，大范围分批审查，缺口不猜测 | 核对单需求、跨模块、历史、排版、缺失基线和分批审查场景；区分文本复核与 Agent 运行 |

## 效果观察

下次业务项目试点时观察：能否找到当前生效要求、能否追溯一次变更至确认来源和验收证据、是否出现重复维护或重复询问已确认决定。尚无试点样本、耗时基线或目标值，不宣称效率提升。
