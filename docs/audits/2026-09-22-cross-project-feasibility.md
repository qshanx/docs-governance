# 产品文档管理与审计护栏：跨项目可行性评估

日期：2026-09-22。评估对象：[草稿 PR #12](https://github.com/qshanx/docs-governance/pull/12)，代码基线 `05ccd97`。本次只读调研其他项目，没有安装钩子、修改文件或执行业务脚本。以下只保留匿名结构统计和可用临时夹具复现的证据，不公开本地业务路径与文档正文。

## 结论

**文档管理思路可行；当前实现适合受控试点，不适合直接向所有项目安装强制护栏。应把接入适配评估加入文档管理方法，作为启用规则前的依据。**

完整十阶段入口继续保留。适配改变的是实际路径映射、扫描范围与规则，不减少阶段，也不接管 PM 专业判断。

本插件自身 54 个测试及 CI 通过，只证明已覆盖的行为，不能替代跨项目兼容性。此次发现的阻碍尚未修复；PR 应保持草稿。

## 覆盖范围与方法

- 读取 Codex 登记的全部 11 个本地项目；另在两个常用开发目录和登记知识目录进行最多六层 Git 仓库发现，共发现 37 个仓库目录，包含父仓、归档、副本和第三方代码。不是 37 个独立活跃产品，也不是全磁盘无遗漏清查；遇到非扫描根的仓库即停止向内发现。
- 对 37 个目录收集 Git 跟踪文件和入口元数据；对登记的 11 个项目进一步采集工作区文件大小、文档候选和 hooks 配置，并运行同一 `audit-docs.py --scope full --format json`。三个并发检查，单项目超时上限 20 秒。
- 文件体积通过 stat 汇总，未为测性能读取业务数据、凭据或大型媒体正文；未在其他项目运行会写缓存的 auto-audit。真实 Stop 行为仅在独立临时夹具中复现。
- 另以真实临时 Git 仓复现缓存、子目录、子项目、旧断链、网站链接和 linked worktree 行为。耗时是本机单次观察，不是性能承诺。
- 工作区会持续变化；本统计描述采样时点。未对所有告警逐条进行语义裁决。

## 本地项目结构的证据

| 观察 | 结果 | 对方案的影响 |
|---|---|---|
| 自身之外的登记项目 | 10 个 | 都不具备本插件完全相同的路径布局；不能整份复制本仓库配置 |
| 含 Python／Shell 的其他登记项目 | 9 个，9 个都有文件位于默认 scripts/hooks/tests 之外 | 业务源码不能按脚本后缀强制搬家，须区分工具脚本与业务源码 |
| 配置了 core.hooksPath | 3 个 | 不能统一覆盖 `.git/hooks`；须识别已有体系并验证组合 |
| 有 pre-commit 文件 | 2 个，含本插件 | 文件存在不证明已执行；其他 pre-push 等也须保留 |
| 完整根四件套 | 6 个，含本插件 | 治理成熟度不同，缺少载体不自动认定文档违规 |
| 十阶段实际组织 | 至少一个业务项目已经有完整十阶段导航，目录命名与本插件不同 | 完整流程可映射已有资料，不需要重复创建同一事实 |

本仓库的 [位置配置](../../.docs-governance.json) 是插件自身规则，不是业务项目的通用默认规则。现有脚本虽支持每项目配置，但尚缺接入评估来指导正确选取范围和例外。

### 工作区体积与只读审计

匿名编号仅表示本次登记样本，顺序不代表优先级。体积按现有 auto-audit 的固定排除规则统计，包含它目前会访问的生成物与嵌套工作区；GiB 按 1024³ 字节计算。

| E | 924 | 0.411 | 1.101 | 65 |
| F | 1894 | 13.553 | 1.380 | 289 |

11 个检查均在 20 秒内返回，除本插件外都返回 1，总计 2452 个 fail 发现。**这是规则命中数，不是 2452 个已确认文档错误。** 抽查发现 API 路径被当本地路径、网站路由、示例语法、生成物以及历史工作区进入范围。不能把这些结果当成项目健康排名。

表中的耗时是 full 审计时间，**不包含 auto-audit 对所有文件逐字节计算指纹的时间**。例如 F 的 13.553 GiB 不是实测读取耗时，但已足以证明现有指纹输入远超文档本身。

## 已复现的可行性边界

| 优先级 | 证据与复现 | 判断及建议 |
|---|---|---|
| P1，推广前修正 | [auto-audit.py](../../scripts/auto-audit.py) 在判断缓存之前读取全部文件；[docpolicy.py](../../scripts/docpolicy.py) 只排除固定目录。临时仓加入被 Git 忽略的 128 MiB 媒体，未变时仍需全量读；仅改媒体一字节就重新审计 | 缓存没有免除读取成本。统一声明治理输入和生成物／数据排除范围，并保留未跟踪文档和链接目标存在性变化的检测 |
| P1，推广前修正 | [Stop hook](../../hooks/check-on-stop.sh) 只查当前目录。根规则要求一个缺失文件，在根调用会报告，在 apps/web 子目录调用却静默 | 明确治理根定位规则，补子目录触发验证。宿主实际 cwd 未验证，不能宣称线上必然漏检 |
| P1，强制前处理 | [暂存审计](../../scripts/check-staged-docs.py) 检查整个 index。临时仓旧 README 有断链，本次仅暂存 app.py 也被阻断 | 全量检查符合现有语义，但不能把历史债务直接变成全部提交的阻塞项。先确认旧问题清单，规划增量阻断或清债后全量启用 |
| P1，相关类型接入前适配 | [链接解析](../../scripts/audit-docs.py) 将 /guide/ 视为系统绝对路径。站点存在 guide/index.md 时仍失败；Git 忽略的 dist 文档也会导致工作区审计失败 | 区分文件链接和站点路由，定义共享审计范围。单条 placement.exclude 不会豁免全局链接检查 |
| 适用条件需明确 | 根规则与 apps/web 子规则并存时，根审计通过而显式审计子项目失败 | 当前只处理传入根配置。Monorepo 先明确根统一治理或独立子项目，不声称自动治理全部子项目 |
| 正向证据 | 临时 linked worktree 的暂存审计及 Stop 基础调用都返回 0 | Git 根和 index 解析基础路径可用；不代表共享 hook、多工作区并发或宿主触发已验证 |

128 MiB 夹具中，无媒体缓存命中约 0.051 秒，有媒体缓存命中约 0.121 秒，媒体变化重审约 0.238 秒。本次小夹具没有出现长时间阻塞；它证明行为，不能线性推算所有仓库耗时。

另有两项源码层风险尚未作为性能故障实测：暂存检查每次导出全部跟踪文件，包含大型二进制；文档孤儿检测会读取大量 Markdown 并相互匹配。已有 hooks 的组合、LFS、submodule、sparse checkout、Windows 和宿主真实触发仍未验证。

## 应增加的接入评估

评估放在产品文档的“需求分析／需求评审”阶段，项目运行记录沿用现有审计目录；不新增第十一个产品阶段，也不创建独立任务看板。

每项目记录以下内容：

1. **适用性**：产品工程、工具、内容资料、第三方或历史副本；是否是需要本插件治理的活动项目。
2. **现有资料映射**：十阶段各指向哪里，哪份是生效主记录，未开展阶段的入口与状态。
3. **治理边界**：项目根／子项目、应扫描文档、应排除的生成物、数据和其他工作区。
4. **既有机制**：core.hooksPath、pre-commit／pre-push、CI 及能否安全组合。
5. **规则适配**：抽查命中及例外，区分真正违规、误报和未验证；不能只报告总数。
6. **存量与成本**：历史发现基线、审计与指纹耗时、暂存导出体积，记录实测环境。
7. **建议启用方式**：可强制、先只读报告并清理旧问题、需要范围适配。理由和证据要能追溯。

试点建议：先选有稳定文档入口、资料体积较小的业务项目验证归位规则；再选已有十阶段空间且资料量大的项目验证路径映射与扫描边界。第三方、备份和知识资料目录也纳入适用性评估，不默认统一安装产品提交护栏。

推广验收至少包括：现有资料无重复迁移；所抽查正常业务源码不误拦；新增错放和断链能被捕获；既有 hooks 保留并经过组合验证；无关媒体变化不引发全仓重读；子目录触发能找到正确规则；旧问题与新增问题有清晰边界。预算和阈值依据项目实测约定，不在本报告虚构统一数值。
