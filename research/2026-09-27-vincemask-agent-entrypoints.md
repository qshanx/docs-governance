## 文章八条要点

按原文 1—8 的顺序整理。第二列是来源观点，第三列是本项目采用方式；不是所有观点都等于宿主功能保证。执行细节只维护在 [Skill 的同序号条目](../skills/agent-entrypoints/SKILL.md)，不在这里维护第二份规范。

| 原文序号 | 原文要点摘要 | 本项目对应落点 |
|---|---|---|
| 1 | CLAUDE.md 至多 200 行；用 30 秒能否回答产品、技术栈、代码位置自检 | 第 1 条：AGENTS／CLAUDE 每份 ≤200 行硬验收、超限分流与实际计数；时间标准只作可读性自检 |
| 2 | 技术栈之外也需禁止清单；文末建议列三个禁用库 | 第 2 条：核对真实禁用项、原因和替代方案，不为数量编造禁令 |
| 3 | 用可判定规则替代主观形容；尝试 5 秒判断是否遵守 | 第 3 条：触发条件、动作、路径／命令和验证依据；不把文章代码风格示例默认应用到所有项目 |
| 4 | 用路由与渐进读取代替把资料全部塞进入口 | 第 4 条：PRD／Spec、地图、架构和历史按任务触发；检查导入是否仍在全量加载 |
| 5 | 在认证、支付、基础设施等高风险目录放局部入口 | 第 5 条：按真实模块风险建立差异规则，检查父子冲突和各宿主的加载范围 |
| 6 | 让 Hooks 执行规则，不只依靠模型记住文字 | 第 6 条：规则与事件、命令、失败行为对应；经授权接入并用成功／失败样本验证 |
| 7 | 用入口指令维护 MEMORY.md，保留跨会话的有效经验 | 第 7 条：提取、去重、保存、下次读取和修正过期经验；复用 MEMORY 或既有 CONTEXT／ADR／LOG 等唯一载体 |
| 8 | 提前保存身份、关注点、厌恶事项与工作风格，减少重复开场说明 | 第 8 条：以已确认约定明确沟通和推进方式，区分团队共识与个人偏好 |

原文文末的四项行动分别对应第 1、2、3、5 条，未另立一套编号。原文强调发现反复踩坑或有效规则后持续维护入口；本项目由第 7 条承接这一反馈回路。文章中的时间和效果说法未在本轮实测。

## 技术核实与纠正

2026-09-27 核对 [Claude Code 记忆文档](https://code.claude.com/docs/en/memory)：

- 200 行是写作目标，非 CLAUDE.md 的硬截断线；导入其他文件仍消耗上下文。
- v2.1.277 起支持直接读取 AGENTS.md。默认遇到工作目录或祖先的 CLAUDE.md／CLAUDE.local.md 时优先读 CLAUDE；版本、设置和内置插件影响支持情况。兼容旧会话可从 CLAUDE 导入 AGENTS；应核对实际加载。
- 子目录规则按访问触发；不能推定其他 Agent 的加载行为相同。

[Hooks 参考](https://code.claude.com/docs/en/hooks)区分事件及其阻断行为。因此需核对具体事件、脚本与失败结果；存在 hook 文件不等于规则已被强制执行。

原文对作者身份和“200 行”建议来源的归因未单独验证；不据此推断软件硬限制。此前本会话“Claude 尚无 AGENTS.md 官方支持”的判断已被上述当前官方说明纠正。

2026-09-27 阿磊随后明确要求补入 200 行硬条件，并按文章原序号体现全部要点。因此本项目将每份 AGENTS.md／CLAUDE.md 的 ≤200 行提升为治理验收规则，取代此前“长度只作复核信号”的处理。规则依据是用户确认；官方写作建议与本项目硬验收须区分。

## 转成 docs-governance 的具体要求

本节是结合本仓库方法论作出的适配，不是原文引述。

| 要解决的协作问题 | 本项目采用的处理 |
|---|---|
| 新 Agent 不知道项目做什么 | 从已确认讨论／产品基线提炼用途、用户与约束；未知技术栈留待确认 |
| 有 PRD／Spec 却从不读取 | 入口写触发条件与真实产品入口；由 product-evolution 定位修订、适用条款及确认依据 |
| 章程只有抽象口号 | 用“触发条件 → 动作 → 路径或命令 → 验证依据”写规则，依赖真实配置和已确认约定 |
| 双宿主规则分叉 | 保留已约定的共享规则主文件，另一入口仅适配；文件名选择与内容规范分开处理 |
| 模板示例变成项目禁令 | 禁用项注明项目原因与替代入口；不凑数量，不擅自要求禁用某库或统一某种导入语法 |
| 资料齐全但缺内容 | 新项目整理已知目标；讨论完成项目连接确认材料；已有项目核对代码与文档差异。区分事实、建议和缺口 |
| 所有经验挤回入口 | 领域知识进 CONTEXT、技术理由进 ADR、事件进 LOG、规范留共享入口或模块规则；仅在既有载体无法承接时考虑新文件 |
| 个性偏好污染团队约定 | 仅保存团队已确认的协作规则；个人约定留个人范围 |

## 与最新文档体系的关系

- [product-evolution](../skills/product-evolution/SKILL.md) 已定义十阶段资料、来源、当前基线与按任务读取。PRD／模块 Spec 保持需求和验收的主记录。
- [living-docs-governance](../skills/living-docs-governance/SKILL.md) 已定义文档职责与分级读取，并非此前完全没有入口规范。独立 Skill 补充的是从项目证据生成具体内容、规则去重、入口选择和交付检查。
- agent-entrypoints 输出有项目内容的入口、必要的适配及规则缺口；它可以由当前 Agent 或未来 setup 编排 Agent 调用。它本身不批准 PRD，也不承担完整产品文档包的编写。
- 当前仓库仍以 CLAUDE.md 为共享章程、AGENTS.md 为桥接。引入独立 Skill 不自动迁移这个约定；现有审计和模板仍有这一默认布局，迁移需一并适配并验证。
