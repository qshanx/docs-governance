# 模块两入口与边界核对示例

虚构订单／库存项目，以下约定仅用于复核流程，不能直接当成目标项目事实。通过总路由或 change-impact 进入 architecture-docs，按主文件的六步逐项核对；不是仅搜索关键词就宣布通过。

## 最小布局

```text
AGENTS.md                  # 项目共享规则：修改前读取适用模块入口
ARCHITECTURE.md             # 已有模块关系总览，不另造一套地图
modules/inventory/
  AGENTS.md                # 库存职责、公开入口、契约指针、简短决策
  CONTEXT.md               # 库存上下文术语
  public.ts                # 已有公开类型／函数，字段唯一来源
  internal/store.ts        # 私有状态实现
modules/orders/
  AGENTS.md
  CONTEXT.md
  checkout.ts
```

库存 AGENTS 内容样例（不是自动生效的宿主配置）：

```markdown
# 库存模块
适用于 modules/inventory/；同时遵守根规则。
负责预留、释放库存，不负责订单付款。只有本模块写库存状态。
公共入口为 public.ts，其他模块不得导入 internal/。
## 接口契约
拥有者：库存模块；类型与行为入口：public.ts；版本依据：受检 Git 提交。
兼容约定：调整公开参数前核对订单消费者，不单方移除参数。
验证：复用项目 TESTS 中库存提供者与订单消费者的实际命令。
## 决策 inventory-001
Status: accepted；确认来源：本虚构案例给定约定。
Context: 订单需要预留库存；Decision: 通过公开接口预留。
Alternatives: 订单直接写库存；Reason: 库存统一维护不变量。
Consequences: 调用方须处理预留失败，接口变更需消费者同步；可通过兼容入口迁移。
Related: public.ts；Supersedes: 无。
```

CONTEXT 只定义“可用量”“预留量”及业务关系，不复制接口签名、上述决策或测试结果。本例命令尚未指定，必须判“验证命令待补”，不能假设存在 npm 脚本。

## 验收场景

开发流程还应区分以下情况：

- 只优化库存内部查询，不改变词义、接口和状态归属：合读两入口及相关定义后，在授权内实现并验证；不强制更新未变化的文档。
- 把“可用库存”从未预留数量改成包含在途数量：不能当成变量改名直接实现；先查业务确认，核对双方 CONTEXT、接口语义与测试，未确认的部分暂停。
- AGENTS 允许订单直接扣库存，但 CONTEXT 对应的库存归属说明指向另一份生效规则：报告来源冲突，查确认记录，不自行选择较新文件；不把术语文本当修改权限。
- 只有 AGENTS 或只有 CONTEXT：找既有规则／词汇表替代，必要资料仍缺失就列缺口；不以“读过一个”宣称已理解两类知识。

| 输入事实 | 应有结论 |
|---|---|
| checkout 经 public.ts 调 reserve，库存自身执行写入；调用与定义均可追溯 | 这条静态链路与约定一致；业务测试未运行仍为未验证，不背书全项目 |
| checkout 从 inventory/internal/store 导入并修改库存 | 同时报告私有入口越界与状态写入冲突，附实际代码位置和上方两条规则；不能把规则改成允许来消除告警 |
| 别名 @stock 重导出 internal/store | 追踪别名／重导出到真实定义；不能因导入不含 internal 就判通过 |
| 通过运行时配置选择未知处理器 | 静态检查不足，列配置／运行证据缺口；没有命中不等于无依赖 |
| 订单的“可用”表示可下单，库存的“可用”表示未预留数量，两边明确映射 | 属于不同上下文，不能为全项目同词而强制统一定义 |
| 已有 CONTRACT.md、docs/adr/0001-*.md | 模块入口只链接原主记录；不复制字段、不搬走或删掉历史 |
| 决策 inventory-002 替代 inventory-001 | 新旧互链，旧标 superseded 并保留；proposed 不冒充当前约定 |
| 入口长度超 200 行 | 长度失败，下沉详细决策到既有 ADR 主记录并留指针，不能删历史凑行数 |
| 只有目录，没有明确模块边界或状态规则 | 先列待确认事实，不批量生成 AGENTS／CONTEXT，不臆造架构违规 |

上述为规范场景的预期判定。真实项目验证还须提供受检快照、实际文件／行号、执行回执和覆盖缺口；现有链接／ADR 审计不自动证明内联决策或代码边界一致。
