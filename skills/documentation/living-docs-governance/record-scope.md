# 记录范围与模板

沿用项目已有的同类文档；setup 接好正文、导航和状态，按实际需要记录，不编造内容或凑齐固定文件。`CLAUDE.md／AGENTS.md` 沿用已确认的共享主源，具体入口规则交给 `agent-entrypoints`。

项目文档只记录团队共享的事实与约定；个人偏好沿用宿主的个人配置，不写入共享规则。

| 文档 | 何时需要／更新 | 什么值得记录 | 不记录什么 |
|---|---|---|---|
| `CLAUDE.md／AGENTS.md` | 项目将持续维护，需要共同约束；约定变化时更新 | 后续任务持续适用的项目约束、必要操作规则、按需读取指针；例如“数据库迁移必须兼容旧版本” | 单次任务要求、临时进度、长篇知识正文 |
| `CLAUDE_MAP.md` | setup 时建立或复用导航；路径、入口或误导区变化时更新 | 单看文件树容易找错、需要反复探索才能知道的定位信息；例如“订单校验实际在共享包，旧目录只做兼容” | 完整目录树、容易直接找到的文件、详细架构说明 |
| `PROJECT_STATUS.md` | setup 时建立或复用状态记录；风险、待办、验证或删除项变化时更新 | 会影响下一步行动的当前事实：阻塞、风险、关键验证结果、待确认事项，以及容易被误重建的删除项；已有 Tracker 的事项只引用 | 每次操作过程、已结束且无后续影响的事项、无来源的健康判断 |
| `PROJECT_LOG.md` | 使用 Git 时不默认新建或要求维护；无 Git 时按追溯需要建立；已有历史保留，后续沿用确认约定 | 后续可能需要追溯的重要变化：功能交付、行为调整、故障修复、迁移或删除；记录发生了什么、原因和结果，细节链接出去，历史按规则追加 | 每次编辑、命令输出、聊天流水、重复粘贴 Git／PR／Issue 或其他文档 |
| 复盘沉淀（retro） | 阶段收尾、收到纠正或同类问题反复出现 | 反复出现的问题、用户纠正、非显然的故障原因，以及验证有效的方法；说明发生条件、经验和下次如何处理 | 空泛感想、未经验证的猜测、只适用于一次任务的偶然细节 |

同一信息只在一处维护，其他文档引用。Agent 项目工作环境按 `skills/engineering/project-retro/SKILL.md` 从指定经历复盘并提出建议；经验保存、复验和升级按需处理，来源留原记录。文档内容与测试资产继续由对应专项 Skill 维护，写入遵守已有授权。日志统计见[日志统计](log-management.md#日志统计)，不另复制经验方法。

事实按类型认来源：规则、决策与历史由相应文档维护，接口字段由唯一机器契约定义；测试与审查结论引用实际运行的版本、范围、结果和证据位置。项目已有工程 Skill 继续负责代码审查，治理层只核对与引用其证据。STATUS 保存带来源的健康快照，相关实现或验收条件变化后标待复验，不把旧绿色结果延续为当前结论；无法确认版本或范围时明确写未验证。

## 读取与模板

由 `skills/documentation/agent-entrypoints/SKILL.md` 根据项目实际主源设置读取路标：规则入口保持简短，定位资料读 MAP，理解结构读架构，追溯原因查 Git／PR／Issue 或已有 LOG；涉及新建、删除或重命名时核对导航与删除记录。保留已有 AGENTS／CLAUDE 正文，不套桥接模板覆盖主源。

MAP、STATUS 可参考 `templates/CLAUDE_MAP.example.md`、`templates/PROJECT_STATUS.example.md`；仅确定需要 LOG 时参考 `templates/PROJECT_LOG.example.md`；其他模板由专项 Skill 选择。示例数值、路径与结论不能当作项目事实。
