# 项目治理规则与工作流落点检查

输入为目标项目根、任务范围、规则与资料入口、现有 Skills 和自动化配置。管理治理规则的分工，不代替需求、架构和测试等专项判断。

1. **固定范围。** 读取项目共享入口、地图与任务要求，记录基线和未提交变化。全局配置、个人记忆与历史会话不在本检查范围。
2. **按需采集。** 执行[规则与工作流落点检查](supporting-files/rule-placement.md)，沿代表性任务检查入口、规范、Skill、参考和已有自动化；大型项目分批，明确未覆盖项。仅需项目健康静态证据时，复用 [living-docs-governance](../living-docs-governance/SKILL.md) 的项目健康采集流程。
3. **判断落点。** 优先复用已有 Skill、附件、脚本和触发链。将项目事实与可复用方法分开，保留核心约束、主源与历史依据；不因一份文档长就新建 Skill。
4. **交付并停止。** 输出“规则／工作流 → 证据与版本 → 当前载体 → 建议落点 → 最小下一步 → 验证办法”，区分问题、未发现问题、不适用和未验证。只读交付即停止；不迁移正文、合并或删除 Skill、安装 Hook 或修改门禁。证据不足只暂停依赖该证据的结论。

规则文字与配置存在不证明宿主行为有效。后续实施须有对应授权；此检查不自动执行所发现的命令。从指定对话与项目证据提炼、复验和升级经验，统一使用 [project-retro](../../engineering/project-retro/SKILL.md)；本检查不隐式扫描会话历史。
