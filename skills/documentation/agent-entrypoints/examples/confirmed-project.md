# 示例：项目信息如何变成 AGENTS.md

这是虚构的“设备借用台账”项目，用于展示写法，不是本插件的项目规则或真实测试证据。假设下列事实均已由项目资料和负责人确认；输出中的路径相对该示例项目，不相对本插件。

## 输入

| 已知事实 | 具体内容 |
|---|---|
| 产品与范围 | 为小团队登记办公设备借出、归还；首版单机离线使用，不做采购或财务核算 |
| 技术栈与代码 | Python 3.12、Flask、SQLite；业务代码在 `src/asset_lending/`，页面模板在其 `templates/`，测试在 `tests/` |
| 当前阶段 | 需求已确认，已有实现和测试；此前没有 Agent 入口，本次选 AGENTS.md 为共享主源，当前宿主为 Codex，不需要另建 CLAUDE.md |
| 依赖限制 | 为保持离线和单机部署，不引入 Redis、MySQL 或外部 SaaS；持久化沿用 SQLite |
| 验证入口 | 项目开发说明登记：激活已有 `.venv` 后在根目录运行 `python -m pytest -q`；尚未配置自动测试 Hook |
| 现有资料 | 产品入口 `docs/product/README.md`、需求主记录 `docs/product/06-prd.md`、`CLAUDE_MAP.md`、`ARCHITECTURE.md`、`docs/testing.md`、`docs/working-notes.md` 均已存在 |
| 协作约定 | 中文沟通、先结论后证据；允许收尾时同步已验证经验并按依据清理过时规则；推送仍需用户明确要求 |
| 局部规则 | 当前未发现需要单独约束的高风险模块，不创建模块级入口 |

## 完整输出

见 [agents.example.md](agents.example.md)。它展示目标项目根目录的 AGENTS.md 成品，不是待填模板；不要把示例的技术栈、禁用项和路径套到其他项目。

## 与八条规范的对应

| 序号 | 成品中的体现 |
|---|---|
| 1 | 简短入口、200 行约束；交付前调用长度脚本 |
| 2 | 禁用项及离线／单机原因、SQLite 替代方案 |
| 3 | 明确工作目录、测试命令和失败处理 |
| 4 | 产品、地图、架构、测试和经验的按需读取路标 |
| 5 | 本例无模块独有约束，因此不创建局部入口 |
| 6 | 明确尚无自动 Hook，手动检查不冒充已强制执行 |
| 7 | 复验后保存经验、下次相关任务前读取；按依据清理过时规则，保留有效红线 |
| 8 | 中文、结论优先、报告证据、推送确认边界 |

本例只验证写法和入口长度。没有运行虚构项目的测试，也没有验证宿主加载效果。技术栈未定的新项目应如实保留待定项；已有 CLAUDE 主源的项目应保留原主源，不能照此改成 AGENTS 主源。

交付证据示例（仅展示表达）：`python -m pytest -q` 已从开发说明定位，但未运行，退出码无；原因是本例没有业务代码。不能写成“测试通过”。路径与宿主加载也不能因出现在虚构输入表中就判已验证。
