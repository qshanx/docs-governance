# 项目经验复盘

从实际工作中提炼下一次能找到、采用和验证的项目经验。用户要求或项目约定阶段复盘时执行；同类问题反复出现时可建议复盘，不默认每轮总结。默认只读，文档同步和审计分别由对应 Skill 负责。

## 1. 找到相关记录

明确复盘的任务或问题；未指定时只看当前任务及其会话。按问题、模块或关键词检索相关对话、项目历史记录，再沿链接读取 PR、Issue、决策和验证证据，不全量加载历史。说明实际读取范围与缺失材料，不凭印象补全过程。

## 2. 找值得留下的经验

沿以下六个方向找候选，不要求每次凑齐：

| 方向 | 去哪里找、重点核对什么 | 值得留下什么 |
|---|---|---|
| 用户纠正 | 对话中的纠正及后续确认：是一次要求，还是反复适用的约定？ | 已确认的稳定约定及适用范围 |
| 重复踩坑 | LOG 的故障、返工记录及关联 Issue：同类问题为什么再次发生？ | 原因、预防办法和验证入口 |
| 难找的知识 | 对话中的反复搜索、定位过程：哪些关系无法从目录看出来？ | 导航指针、隐含依赖和定位提示 |
| 决策理由 | 讨论、PR、ADR：为什么选这个方案，哪些条件限制了选择？ | 已确认的理由、取舍及重新评估条件 |
| 有效做法 | 成功处理问题的过程和测试证据：什么办法在什么条件下有效？ | 可复用步骤、必要条件和验证方法 |
| 过期或冲突经验 | 历史结论对照当前实现、需求和主记录：哪些已失效或互相矛盾？ | 修订或替代依据，保留历史上下文 |


## 3. 判断是否可复用

对照来源、当前实现、已确认需求和已有措施，判断经验在什么条件下仍然成立。实现与需求冲突分别记录；普通进度、一次性操作和原因猜测不升级为长期规则。

只保留能改变下次行动的经验，合并重复；已有措施就核对它是有效、未接入还是失效。一次失误不直接变成永久禁令，证据不足列待验证建议；没有新发现就不新增内容。

## 4. 指出落点和下次怎么用

按影响排序，每条写“适用情况 → 下次行动 → 证据 → 具体主记录与读取时机”，沿用项目现有路径：

- 稳定约定 → AGENTS／CLAUDE，按 `agent-entrypoints` 取舍，长说明留指针。
- 导航知识 → MAP；领域术语 → CONTEXT；重要决策 → ADR；可复用步骤 → 对应操作文档。
- 可自动防止的重复错误 → 现有测试或检查，先查已有机制，避免重复建设。
- 重要改进事件 → 项目约定的历史主源；已有 LOG 按约定追加索引，否则复用 PR／Issue／决策或能承载原因、依据和版本的 Git 记录，不另建流水，保留原有历史。经验正文只维护一处。

例如：接口改名后，相关指南的调用示例曾失败；复验确认有效的检查方法应进入现有接口验证指南，并从接口变更任务入口指向它，附失败与复验依据。

默认在回复交付建议；获准落实后更新对应主记录，新增检查或外部任务须在授权范围内。区分建议、已落实和已验证；写入文档不等于效果已验证。完成时说明范围与缺口，每条经验都应有依据、适用条件、具体动作和下次可找到的落点，不默认另建报告、MEMORY 或 Skill。
